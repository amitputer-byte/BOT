# CLAUDE.md — גן הכפל

> הקובץ הזה נטען אוטומטית בכל סשן. שמור אותו קצר. הנחיות למשימה ספציפית נמצאות בקובצי spec נפרדים, לא כאן.

## מה זה
אפליקציית לימוד לוח הכפל לילדים — עברית RTL, offline. קובץ HTML יחיד עצמאי שנבנה מפרויקט Vite. משתמשת בה תמרי, עם תמיכה בפרופילים נוספים. מנוע spaced-repetition אמיתי + state machine של שליטה (new → practicing → strong → mastered → at_risk), ~10 משחקים, חנות/חיות/קישוטים, מפת עולם, דשבורד הורים, PWA.

## כללי ברזל (לא משתנים)
- **אפס אובדן נתונים.** כל נגיעה ב-state קיים → גיבוי גולמי תחילה. שום פעולה הרסנית בלי גיבוי.
- **offline-first.** אפס תלות רשת בזמן ריצה — אין CDN, אין `fetch` חיצוני, אין פונט חיצוני.
- **עברית RTL מלאה.** שום רגרסיה בכיווניות.
- **פרטיות.** שום ענן, שום tracking, שום egress — הנתונים נשארים על המכשיר.
- **בנייה לקובץ יחיד.** ההפצה תמיד קובץ HTML עצמאי אחד שעובד offline.
- **לא לרגרס.** כל המשחקים והפיצ'רים הקיימים חייבים להמשיך לעבוד אחרי כל שינוי.

## אחסון (קריטי)
- כל קריאה/כתיבה של state עוברת דרך **שכבת ה-storage היחידה**. אסור `localStorage` מפוזר בקוד.
- כל בלוק שמירה נושא `schemaVersion`. כל שינוי סכמה → migration function + טסט מיגרציה. לעולם לא לשנות צורת שמירה בלי מיגרציה בדוקה.
- ה-state הוא per-profile. שום דליפה בין פרופילים.

## פקודות
- `npm run dev` — פיתוח
- `npm run build` — בונה קובץ HTML יחיד offline ל-`dist/`
- `npm test` — engine tests + jsdom flow tests

## איך לעבוד
- **קרא קודם, כתוב אחר כך.** הבן את הקוד הקיים לפני שינוי. אל תנחש מבנה שמירה — אמת מהקוד.
- **טסטים לפני ואחרי.** הרץ `npm test` כבסיס לפני שינוי; חייב להישאר ירוק אחרי.
- **שינויים קטנים, commits קטנים** עם הודעה שמתארת בדיוק מה השתנה.
- **אל תערבב refactor עם פיצ'רים חדשים.** בסיס יציב קודם, פיצ'רים אחר כך.
- בעברית מול אמית. קוד / identifiers / paths באנגלית.

## מבנה הפרויקט
> סעיף חי — עדכן אותו ככל שהפרויקט מתפתח, כדי שסשן עתידי יתמצא מהר.
- `index.html` — נקודת הכניסה של Vite (head + `<style>` + `#app` + `<script type="module" src="/src/main.js">`).
- `src/engine.js` — מנוע הלמידה הטהור (spaced-repetition + state machine) + עוזרים טהורים: דרגות/כוכבים/מסע, תחזית סיכון + תאריך שליטה, גנרטורי חיבור, ועוזרי engagement (יעד יומי/פרס התחברות/אתגר שבועי/ערכת נושא). ESM, נטען גם ע"י הטסטים.
- `src/storage.js` — **שכבת האחסון היחידה** מודעת-הפרופיל: registry, מצביע פעיל, state per-profile, `schemaVersion` + framework מיגרציות, מיגרציית legacy אידמפוטנטית עם גיבוי גולמי, **מראה IndexedDB + גיבוי אוטומטי יומי + שחזור**, וייצוא/ייבוא פרופיל בין מכשירים. כל I/O ל-localStorage עובר מכאן.
- `src/app.js` — שכבת האפליקציה: UI, ניתוב (`go`/`render`), 11 משחקים, מרכז תרגול (חיבור עד 100 + שאלות מילוליות), חנות/חיות/קישוטים, מפת עולם + סיפור, חדר גביעים/אוספים, יעד יומי/אתגר שבועי/מתנת התחברות/בן-לוויה, נגישות, אונבורדינג, בחירת/הוספת/החלפת פרופיל, דשבורד הורים מנבא. משתמש ב-`ENGINE` וב-`Storage`.
- `src/main.js` — entry שמייבא את `app.js`.
- `test/engine.test.js` — רגרסיית מנוע + עוזרים טהורים. `test/storage.test.js` — מיגרציה, בידוד פרופילים, עמידות (IndexedDB) וייצוא/ייבוא. `test/flow.test.js` — jsdom: boot, RTL, טעינת כל המשחקים וכל המסכים.
- `gan-hakefel.baseline.html` — צילום המקור לפני הרפקטור (נקודת חזרה).
- בנייה: `npm run build` → `dist/index.html` (קובץ יחיד, inline module, offline).

## פרופילים (מודל אחסון)
- מפתחות: `gankefel:registry` (registry + `activeProfileId` + `legacyMigrated`), `gankefel:profile:<id>` ל-state של כל פרופיל, `gankefel:legacy-backup` לגיבוי הגולמי של השמירה הישנה.
- `Profile = { id, name, avatar, createdAt }`. ה-legacy הישן (`gan-hakefel-v1`) עובר לפרופיל "תמרי" פעם אחת, ולא נמחק (רשת ביטחון נוספת).
